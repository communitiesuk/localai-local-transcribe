# LLM Token & Cost per Meeting

Per 1-hour meeting (9,000 transcript words, 2 tokens/word). BEST = gpt-5.1, FAST = gpt-5-nano. Output includes a 15% reasoning-token allowance; cached prefixes are billed at a pessimistic 75% hit rate. Generated by `documentation/env_assets/llm_cost.py`.

This estimate includes the citation tier change: no prompt text changes, but `extract_claims` and `cite_claims` move from FAST to BEST for citing templates. Everything else keeps its current tier.

Prices are list prices in GBP, from:

- [Azure OpenAI pricing](https://azure.microsoft.com/en-us/pricing/details/azure-openai/) — Sweden Central, Data Zone rates
- [Azure AI Speech pricing](https://azure.microsoft.com/en-us/pricing/details/speech/) — UK South

The change applies once per generated minute, not per section: one `extract_claims` call and one `cite_claims` call. `extract_claims` sends static instructions plus the full draft summary and returns a JSON list of atomic claims. `cite_claims` sends static citation policy, the full indexed transcript, the claims list and the full draft, then re-emits the cited summary plus `claim_citations`. For a 1-hour meeting, `cite_claims` is the expensive leg because the indexed transcript dominates input.

Executive Summary has `citations_required = False`, so it is unchanged. The same is true for custom user-template question generation and the other non-citation calls: meeting title, speaker predictions, the accuracy guardrail, AI edits and the eval judge all keep their current tiers. A precise per-template estimate still depends on the production template mix; the blended usage-weighted figure above uses the existing December 2024-May 2026 mix in `assumptions.yaml`.

## Transcription

Azure AI Speech is billed per hour of audio, so a 1-hour meeting costs whichever rate its adapter charges:

| Path | Adapter | Max audio | GBP per hour |
|---|---|---|---|
| Fast Transcription | `azure_stt_synchronous` | 2 hours | £0.271 |
| Batch Transcription | `azure_stt_batch` | 4 hours | £0.136 |

Selection is by audio duration, not by cost. `TranscriptionServiceManager.select_adaptor` (`common/services/transcription_services/transcription_manager.py:56`) walks the configured `TRANSCRIPTION_SERVICES` list in order and returns the first adapter whose `max_audio_length` covers the recording. Fast is listed first, so anything up to 2 hours goes to Fast; 2–4 hours falls through to Batch; longer than 4 hours raises. Fast is synchronous — one HTTP call that blocks until the transcript comes back — while Batch submits a job and is polled, which is why the cheaper path is only used when Fast cannot take the file. Note the deployed ECS task definition currently sets `TRANSCRIPTION_SERVICES=["azure_stt_synchronous"]`, so in production every meeting takes the Fast path today; `.env.example` enables both.

At £0.271, transcription is about 1.2x the LLM cost of the same meeting: roughly £0.49 per 1-hour meeting for both AI stages.

## Conclusion

With citations on BEST, the blended LLM estimate is about £0.22 per 1-hour meeting, roughly double the previous production estimate on this branch. The result stays within the existing lower/upper bounds: previous Production is the floor, and All-best remains the ceiling. It lands closer to the ceiling because citation is the largest remaining FAST step that ingests the full transcript.
